# Lyra v0.1 — Design Spec

**Status:** Approved (product design)  
**Date:** 2026-07-27  
**License:** MIT  

## 1. Product summary

Lyra is a native, lightweight, local-first Markdown editor and knowledge vault for macOS. It is an open-source alternative focused purely on editing and navigating local Markdown files — no Electron, no cloud sync, no proprietary formats.

Inspired by the simplicity of tools like Obsidian for local vaults, but built as a proper native SwiftUI macOS app.

**Primary goals:** speed, native feel, pure Markdown files on disk, excellent editing experience, and being highly AI-agent friendly from day one.

### Name origin

The name **Lyra** comes from the constellation Lyra and the mythical lyre of Orpheus — the instrument associated with poetry, knowledge, harmony, and the music of the spheres. It reflects a tool for organizing and composing personal knowledge with elegance and clarity.

### Platform & constraints

| Constraint | Choice |
|------------|--------|
| Platform | macOS only |
| Minimum OS | macOS 15 Sequoia+ |
| UI | SwiftUI + AppKit where beneficial (TextKit) |
| Language | Pure Swift, modern concurrency (async/await) |
| Architecture style | Clean MVVM-like (observable stores + view models) |
| Data | Plain `.md` files on disk — no database, no lock-in |
| License | MIT |
| Packaging (v0.1) | **Approach A:** single Xcode app target, module-shaped source folders |

## 2. Goals for v0.1

- Open a local folder as a “vault”
- Sidebar with recursive file/folder tree of `.md` files
- High-quality Markdown source editor with basic syntax highlighting
- Live preview (side-by-side or toggleable)
- Basic wiki-style links `[[Note Name]]` (resolve to files in the vault)
- Create / rename / delete notes and folders
- Autosave
- Native macOS UI; keyboard-first; low memory
- Complete open-source repository scaffolding (README with name origin, AGENTS.md, CONTRIBUTING, architecture docs) so AI agents can extend the project safely

### Explicit non-goals (v0.1)

- Plugins, graph view, tags database, full-text search index
- Cloud sync, accounts, proprietary note formats
- iOS / multiplatform
- Theme marketplace, plugin host
- Electron / WebView-first architecture (WebKit preview only as a documented fallback if native preview is too weak)
- Line numbers in the editor
- UI tests (manual checklist only)

## 3. Packaging decision

**Approach A — Xcode app target + thin module-shaped folders**

- Native `Lyra.xcodeproj` with one macOS app target
- Internal folders: `App/`, `Vault/`, `Editor/`, `Preview/`, `Models/`
- No `Package.swift` in v0.1; folder boundaries allow a later split into SPM libraries (Approach C) without a rewrite
- Sandbox on, with user-selected file read/write and security-scoped bookmarks for reopening the last vault
- Suggested bundle ID: `app.lyra.Lyra`
- Deployment target: macOS 15.0

**Rejected for v0.1:** pure SPM executable (no real `.app` UX); full SPM-core + Xcode shell (extra wiring before first window).

## 4. Architecture

### Layer map

```
┌─────────────────────────────────────────────────────────┐
│  LyraApp (SwiftUI)                                      │
│  Window → NavigationSplitView                           │
│    Sidebar │ Editor │ Preview (optional)                │
└────────────┬──────────────────┬─────────────────────────┘
             │                  │
    ┌────────▼────────┐  ┌──────▼──────────┐
    │ VaultStore      │  │ EditorViewModel │
    │ tree, CRUD      │  │ open path, text │
    │ selection       │  │ autosave        │
    └────────┬────────┘  └──────┬──────────┘
             │                  │
    ┌────────▼────────┐  ┌──────▼──────────┐
    │ FileSystemVault │  │ MarkdownSource  │
    │ enumerate .md   │  │ TextKit highlight│
    │ read/write      │  │ + LivePreview   │
    │ wiki resolve    │  │ (swift-markdown)│
    └─────────────────┘  └─────────────────┘
```

| Folder | Responsibility |
|--------|----------------|
| **App/** | `LyraApp`, main window, menus, open-vault flow, empty states |
| **Vault/** | Tree enumeration, CRUD, wiki-link resolution, security-scoped access |
| **Editor/** | Source editor (TextKit 2 via `NSViewRepresentable`), view model, autosave |
| **Preview/** | Live Markdown preview from the same source string |
| **Models/** | Lightweight types: vault root, tree nodes, open document |

### Key types

- **`VaultNode`**: `id` (file path string), `name`, `url`, `isDirectory`, optional `children`
- **`NoteDocument`**: `url`, `content: String`, `isDirty`
- **`VaultStore`**: `@MainActor` observable — vault root, tree, selection, CRUD commands
- **`EditorViewModel`**: open note, text binding, dirty flag, autosave task
- **`WikiLinkResolver`**: `[[Note Name]]` → first matching `.md` in vault

### Data flow

1. User picks a folder via `NSOpenPanel`.
2. `VaultStore` starts security-scoped access and stores a bookmark for reopen.
3. `FileSystemVault` recursively scans directories and `.md` files (ignore `.git`, `.DS_Store`, hidden names starting with `.`).
4. Sidebar binds to the tree; non-markdown files are not shown.
5. Selecting a note loads UTF-8 text into `EditorViewModel`.
6. Editor and preview share the same in-memory string.
7. Edits debounce-autosave (~500ms) to the same path; also save on note switch, resign active, and terminate.

### Concurrency

- UI state on `@MainActor`.
- File I/O via `async` (nonisolated helpers or `Task` off main) so large trees do not block the UI.
- No dedicated actors required for v0.1 unless a clear race appears.

### Persistence philosophy

- **Source of truth = disk.** No SQLite or index DB in v0.1.
- Refresh tree after create/rename/delete (and optional manual refresh).
- Last vault path + bookmark data in `UserDefaults`.

## 5. UI and feature behavior

### Window layout

- Primary window: `NavigationSplitView`
  - **Sidebar:** vault tree (folders + `.md`)
  - **Detail:** editor; preview side-by-side or toggled off
- Empty states:
  - No vault → “Open Vault…”
  - Vault open, nothing selected → “Select or create a note”
- Native macOS chrome; keyboard-first

### Vault operations

| Action | Behavior |
|--------|----------|
| Open vault | Directory picker; security-scoped access; scan tree |
| Select note | Load file into editor |
| New note | `Untitled.md` or `Untitled N.md` in selected folder or vault root |
| New folder | Under selection or root |
| Rename | Update on disk; if open note renamed, keep open at new path |
| Delete | Confirm; prefer `FileManager.trashItem` |

### Editor

- Source mode primary; system monospaced font.
- **Basic syntax highlighting (v0.1):** headings, emphasis, code spans/fences, links, list markers, `[[wiki links]]`.
- Implementation preference: **TextKit 2** in `NSViewRepresentable`. If scaffold cost is too high for first compile, temporary `TextEditor` is acceptable with a follow-up to TextKit — still aim for TextKit in v0.1.
- Line numbers: deferred.

### Preview

- Live preview from the same string as the editor.
- Prefer native rendering via **swift-markdown** (or `AttributedString` markdown where sufficient) in a scrollable text view.
- If code-block quality is insufficient, a thin WebKit preview is allowed as a **contained, documented fallback** in `docs/architecture.md`.
- `[[Wiki links]]` in preview: styled as links; click opens resolved note if it exists; unresolved = no-op in v0.1.

### Wiki links

- Syntax: `[[Note Name]]` or `[[Note Name.md]]`.
- Resolve: case-insensitive match on filename stem within vault; first match wins for duplicates.
- Unresolved: distinct style in source highlight; click does nothing.

### Autosave

- Debounce ~500ms after last edit.
- Also save on note switch, window resign active, app terminate.
- Optional ⌘S forces immediate write; no separate save ritual required for normal use.

### Keyboard (v0.1 minimum)

| Shortcut | Action |
|----------|--------|
| ⌘O | Open vault |
| ⌘N | New note |
| ⌘S | Save now |
| ⌘⇧P | Toggle preview |
| ⌘W | Close window (system) |

### Settings (stub)

- Remember last vault.
- Preview visible yes/no.
- No theme engine or sync settings.

|------|---------|

### AI-agent friendliness

- Stable module folders and obvious type names.
- Prefer small files with one primary type each.
- Document invariants in AGENTS.md (disk is source of truth; no Electron; no cloud).
- Keep v0.1 scope explicit so agents do not invent plugins/sync/graph views.

## 7. Testing

| Area | Coverage |
|------|----------|
| WikiLinkResolver | Stem match, case-insensitivity, missing target |
| Vault path helpers | Relative display paths, ignore rules |
| Note naming | `Untitled.md` / `Untitled 2.md` uniqueness |
| File write helpers | Write content to URL |

UI tests deferred. Manual checklist: open vault → select note → edit → autosave → preview → create/rename/delete → wiki link open.

## 8. Implementation order

1. Docs and repo scaffold (README, AGENTS, CONTRIBUTING, architecture, gitignore polish).
2. Xcode project + empty app shell (window, empty states).
3. Vault open + tree.
4. Open / edit / autosave.
5. Basic highlight + preview.
6. CRUD + minimal wiki resolve.

Prefer small, reviewable commits. Resist feature creep beyond this spec.

### Environment note

Full compile and UI run require a Mac with Xcode. Documentation and source scaffolding can land without a Mac; CI may stay docs-oriented until a macOS runner exists.

## 9. Success criteria

v0.1 is done when:

1. Repository is professional and AI-ready (docs listed above are present and accurate).
2. On macOS 15+, a developer can open the Xcode project, build, open a folder as a vault, browse `.md` files, edit with basic highlighting, see live preview, use basic wiki links, create/rename/delete notes and folders, and rely on autosave — all data remaining plain Markdown on disk.

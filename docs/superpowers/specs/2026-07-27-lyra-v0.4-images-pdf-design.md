# Lyra v0.4 — Paste images + export PDF (design)

**Status:** approved for planning  
**Branch:** `feat/v0.4.0`  
**Approach:** A — minimal native (AppKit / PDFKit / SwiftUI; no WebKit, no pandoc)

## 1. Goals

1. **Paste images** like Obsidian: ⌘V with an image on the clipboard saves a file under the vault and inserts a Markdown image reference at the caret.
2. **Export the current note to PDF** via a Save panel, with headings/lists/code/quotes and embedded images.
3. **Live preview shows images**, not only the Markdown syntax.
4. Stay local-first: plain files on disk; no database; sandbox-friendly.

### Explicit non-goals (v0.4)

- Drag-and-drop of image files into the editor (can follow; same writer as paste)
- Whole-vault / multi-note PDF
- Custom PDF themes / CSS
- Wiki-style embeds `![[image.png]]` as a separate syntax (standard `![](path)` only)
- Remote/HTTP images in preview or PDF
- Replacing the app logo (user will provide a new master asset later)

## 2. Image paste and storage

### Attachment location (Obsidian-aligned)

Obsidian lets users set **Default location for new attachments** to a fixed vault-relative folder (e.g. `attachments`). Lyra v0.4 hardcodes one convention:

| Item | Value |
|------|--------|
| Folder | `{vaultRoot}/_attachments/` |
| Create | On first successful paste if missing |
| Markdown syntax | `![](_attachments/<filename>)` (relative to vault root) |

Why `_attachments`: user-requested; underscore sorts early; distinct from note content; portable plain Markdown.

### Paste behavior

1. User has a note open; focus in the source editor.
2. ⌘V (or Edit → Paste) when the pasteboard contains image data:
   - Prefer PNG representation; fall back to TIFF → encode as PNG.
   - Filename: `Pasted Image YYYYMMDD-HHMMSS.png` (local time). On collision, append `-2`, `-3`, …
   - Write atomically under `_attachments/`.
   - Insert `![](_attachments/<filename>)` at the caret (replace selection if any).
   - Mark the note dirty so **autosave** runs as usual.
3. If the pasteboard is not an image, perform normal text paste.
4. If no note is open or the vault root is missing, ignore image paste (or show the existing error alert if a write fails).

### Components

| Piece | Responsibility |
|-------|----------------|
| `VaultImagePaster` (or `AttachmentStore`) under `Vault/` | Ensure `_attachments`, unique name, write PNG data, return relative Markdown path |
| `MarkdownTextView` subclass / paste override | Detect image pasteboard; call store; insert text |
| `EditorViewModel` / `ContentView` | Provide vault root + note context to the text view |

Disk remains source of truth; no index DB for attachments.

## 3. Preview and sidebar

### Preview

Extend `MarkdownPreviewBlocks` / `MarkdownPreviewView`:

- Detect image-only paragraphs or inline image syntax `![alt](path)` (v0.4: treat a paragraph that is solely an image as a block; also allow image as sole content of a list item if cheap).
- Resolve `path`:
  1. Absolute file URL if already absolute (rare)
  2. Relative to **note’s directory**
  3. Relative to **vault root** (covers `_attachments/...`)
- Load with `Image(nsImage:)` / `NSImage(contentsOf:)`.
- Display max width ~480pt, preserve aspect ratio.
- Missing file → short secondary “Missing image: …” label.

Wiki link list at the bottom of the preview is unchanged.

### Sidebar

- Continue listing folders and `.md` files only (existing scan).
- **Hide** the `_attachments` directory from the sidebar tree so the pane is not an empty folder shell. Files remain on disk for Finder / git / preview / PDF.

Do **not** hide other underscore-prefixed folders unless named exactly `_attachments`.

## 4. PDF export (current note only)

### Trigger

- Toolbar button when a note is open (SF Symbol e.g. `doc.richtext` — **not** `square.and.arrow.down`, which reads as Download).
- Optional: File menu command “Export PDF…” with the same action.
- Disabled / no-op when no note is open.

### Flow

1. `editor.saveIfNeeded()` so disk matches the editor.
2. Build PDF from the **in-memory** note text (same content as preview) using AppKit drawing into a PDF graphics context (PDFKit / `NSGraphicsContext` PDF).
3. Page size: **US Letter**. Margins ~54pt. Simple page numbers at the bottom if inexpensive; omit only if layout cost spikes.
4. Map blocks similarly to preview: title-sized headings, body text, monospaced code with light background, blockquote indent, bullets, images scaled to content width.
5. `NSSavePanel` default name `{noteStem}.pdf`, default directory = note’s parent folder.
6. Write PDF data to the chosen URL.

### Images in PDF

Same path resolution as preview. Missing images → short text placeholder, do not fail the whole export.

### Errors

Use existing `store.errorMessage` / alert pattern for write failures and unexpected I/O errors.

## 5. Architecture sketch

```
MarkdownTextView  --paste image-->  AttachmentStore  -->  {vault}/_attachments/*.png
       | insert ![](_attachments/...)
       v
EditorViewModel.text  -->  MarkdownPreviewView (images)
                      -->  NotePDFExporter --> Save panel
```

| Module | New / change |
|--------|----------------|
| `Vault/AttachmentStore.swift` | New: folder ensure, unique name, write PNG |
| `Editor/MarkdownTextView.swift` | Paste override + context (vault root, onInsert) |
| `Preview/MarkdownPreviewBlocks.swift` | Image block + path helpers (pure, testable) |
| `Preview/MarkdownPreviewView.swift` | Render image blocks |
| `Preview/NotePDFExporter.swift` (or `Export/`) | Build PDF data from markdown + vault root + note URL |
| `App/ContentView.swift` | Wire paste context, Export PDF control |
| `Vault/FileSystemVault.swift` | Skip `_attachments` in scan |
| `README.md` | Features for paste + PDF (required by AGENTS.md) |

No new third-party packages.

## 7. Acceptance criteria

v0.4 image/PDF slice is done when:

1. With a vault open and a note focused, pasting a screenshot creates `{vault}/_attachments/Pasted Image ….png` and inserts `![](_attachments/…)` at the caret.
2. Live preview displays that image without leaving the app.
3. `_attachments` does not clutter the sidebar; files exist on disk.
4. **Export PDF…** produces a US Letter PDF of the current note including resolved images.
5. README documents both features; marketing version remains 0.4.0 on this branch.
6. Unit tests cover naming, path resolve, and image-line parsing; smoke script lists any new required files.

# Lyra v0.5 — Note view modes + image paste fix (design)

**Status:** approved for planning  
**Branch:** `feat/v0.5-view-modes`  
**Approach:** A — mode enum + hybrid block Live Preview (no WebKit)

## 1. Goals

1. **Fix image paste** so ⌘V with a clipboard image reliably writes under `{vaultRoot}/_attachments/` and inserts `![](_attachments/<filename>)` at the caret.
2. **Three note modes** (Obsidian-style):
   - **Source** — raw Markdown editor only
   - **Live Preview** — rendered blocks; click a block to edit that block’s raw Markdown in place
   - **Reading** — full-width rendered preview, not editable
3. Keep **disk as source of truth**: one UTF-8 `.md` string owned by `EditorViewModel`; no sidecar format.

## 2. Explicit non-goals (v0.5)

- Full WYSIWYG / rich-text ↔ Markdown round-trip
- Drag-and-drop of image files from Finder (follow-up; same writer as paste)
- WebKit / contenteditable live surface
- Multi-cursor, block drag-reorder, wiki embeds `![[...]]`
- Side-by-side Source+Reading as a fourth layout (can return later)
- Plugins, graph, sync, tags index, iOS

## 3. Note view modes

### 3.1 Enum and persistence

```swift
enum NoteViewMode: String, CaseIterable {
    case source
    case livePreview
    case reading
}
```

- Persist with `@AppStorage` (e.g. key `lyra.noteViewMode`).
- Replace primary reliance on `lyra.previewVisible` side-by-side split for the detail pane.
- **⌘E** cycles: Source → Live Preview → Reading → Source.
- Toolbar: segmented control (or equivalent) for direct selection.

### 3.2 Detail pane by mode

| Mode | Surface |
|------|---------|
| Source | Existing `MarkdownTextView` |
| Live Preview | New `LivePreviewView` (hybrid blocks) |
| Reading | Existing `MarkdownPreviewView` full width |

### 3.3 Mode switch behavior

- Switching modes commits any in-progress Live Preview block edit into `editor.text` first.
- Export PDF / autosave / ⌘S always operate on the full note string after that commit.
- Wiki link navigation from Reading or Live Preview (idle blocks) keeps current behavior via `VaultStore.resolveWikiLink`.

## 4. Live Preview — hybrid blocks

### 4.1 Model

Reuse `MarkdownPreviewBlocks.parse` so Reading and Live Preview share one block grammar.

Extend parsing (or a sibling helper) to attach **source ranges** for each block in the full note string (UTF-16 / `NSRange` consistent with `NSString` for splice safety).

Each block:

| Field | Role |
|-------|------|
| Kind + display payload | Same as today (heading, paragraph, list, quote, code, image, thematic break) |
| `range` in full source | Inclusive span of raw Markdown for that block |

### 4.2 Interaction

| State | Behavior |
|-------|----------|
| Idle | Blocks render like `MarkdownPreviewView` (including local images and wiki-link list). |
| Activate | Click a block → inline source editor shows only that block’s raw Markdown. |
| Commit | Blur, click another block, or Esc → splice editor text into full note at the block’s range; re-parse entire note; re-render. |
| Empty note | Single empty editable block so typing can start. |

### 4.3 Edit rules

- On commit, replace the old range with the new substring, then **re-parse the whole note** (simplest correct approach when one edit introduces multiple blocks).
- Empty commit: prefer leaving a single empty line rather than deleting the only block.
- Non-focused blocks remain non-editable; wiki links on them stay clickable.
- Image blocks idle-render the image; when focused, user edits the raw `![](...)` line.
- Focused block uses the same paste path as Source (`LyraTextView` or shared helper) so image paste works in Live Preview.

### 4.4 Components

| Piece | Responsibility |
|-------|----------------|
| `NoteViewMode` | Mode enum + cycle |
| `LivePreviewView` | Block list, focus index/id, commit/splice into binding |
| Range-aware parse | Blocks + source ranges |
| `ContentView` | Mode chrome; choose Source / Live / Reading surface |
| `EditorViewModel` | Unchanged ownership of text + autosave; optional `commitPendingEdit` hook if needed |

## 5. Image paste fix

### 5.1 Current behavior (v0.4)

`LyraTextView.paste` attempts `NSImage(pasteboard:)` → `AttachmentStore` → `insertText("![](…)")`. Failures fall through silently; Edit menu may call `pasteAsPlainText:` instead of `paste:`.

### 5.2 Required changes

1. Override **`paste`** and **`pasteAsPlainText`** with one shared image-or-super helper.
2. Broader image intake: `NSImage(pasteboard:)` plus explicit PNG/TIFF/`public.image` pasteboard types if needed.
3. If write fails (or unexpected I/O error): surface a user-visible error (e.g. `VaultStore.errorMessage` or callback); **do not** insert a broken link.
4. If `vaultRoot` is nil: fall through to normal text paste (image-only pasteboard may no-op).
5. Ensure successful insert updates the SwiftUI binding / `textDidChange` path.
6. Keep storage contract from v0.4:

| Item | Value |
|------|--------|
| Folder | `{vaultRoot}/_attachments/` |
| Filename | `Pasted Image YYYYMMDD-HHMMSS.png` (+ `-2`, `-3`, … on collision) |
| Markdown | `![](_attachments/<filename>)` relative to vault root |

## 6. Error handling

| Case | Behavior |
|------|----------|
| Image paste, no vault | Fall through to normal paste |
| Image write failure | Show error; no markdown insert |
| Live Preview commit, no open note | No-op |
| Unresolved wiki link | Unchanged (no navigate) |

## 7. Testing

### 7.1 Unit

- Parse **with ranges**: for a multi-block fixture, each range’s substring equals the block source.
- Splice round-trip: replace one block’s range → expected full string.
- Edges: first/last block, fenced code, image-only line, empty document.
- Existing `AttachmentStore` tests remain; extend pure helpers if new logic is extracted.

### 7.2 Manual

1. Source: copy image → ⌘V → file under `_attachments/`, link in note, image visible in Live/Reading.
2. ⌘E cycles three modes; mode persists across relaunch.
3. Live Preview: edit a heading block, blur, re-render; ⌘S / autosave persist to disk.
4. Reading: content not editable.
5. Export PDF from each mode after any live edit is committed.
